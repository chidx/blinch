# x402 Payment Protocol

The Blinch backend implements the x402 protocol for monetized API access using Bitcoin Cash payments.

## Overview

x402 is an HTTP extension that uses status code 402 (Payment Required) to request payment before granting access to protected resources.

## Flow

```
┌─────────┐                    ┌──────────────┐                    ┌─────────────┐
│  Agent  │                    │ Blinch API   │                    │   BCH       │
└────┬────┘                    └──────┬───────┘                    └──────┬──────┘
     │                                │                                   │
     │  1. GET /api/protected/data     │                                   │
     │ ──────────────────────────────> │                                   │
     │                                │                                   │
     │  2. 402 Payment Required        │                                   │
     │ <────────────────────────────── │                                   │
     │     X-Payment-Link: bitcoincash:...                                  │
     │     X-Payment-Amount: 1000      │                                   │
     │                                │                                   │
     │  3. Use MCP to create payment  │                                   │
     │ ──────────────────────────────> │                                   │
     │                                │                                   │
     │                                │  4. Broadcast transaction       │
     │                                │ ───────────────────────────────> │
     │                                │                                   │
     │                                │  5. Transaction confirmed       │
     │                                │ <────────────────────────────── │
     │                                │                                   │
     │  6. Retry with X-Payment header │                                   │
     │ ──────────────────────────────> │                                   │
     │     X-Payment: <txid>          │                                   │
     │                                │                                   │
     │                                │  7. Verify on-chain              │
     │                                │ ───────────────────────────────> │
     │                                │                                   │
     │                                │  8. Payment confirmed            │
     │                                │ <────────────────────────────── │
     │                                │                                   │
     │  9. 200 OK + Protected Data    │                                   │
     │ <────────────────────────────── │                                   │
     │                                │                                   │
```

## Headers

### Request Headers

**X-Payment**: Transaction ID of the payment

```
X-Payment: 0a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6e7f8a9b0c1d2e3f4a5b6c7d8e9f0a1b2
```

### Response Headers (402 Payment Required)

**X-Payment-Link**: Blinch payment URL

```
X-Payment-Link: bitcoincash:qzp2wq8l9r5h6l7x8z9c0b1n2m3k4j5k6l7z8c9b0n1?amount=0.00001&op_return=464c4f5701api_access
```

**X-Payment-Amount**: Required payment in satoshis

```
X-Payment-Amount: 1000
```

**X-Payment-Currency**: Currency (always "sat" for satoshis)

```
X-Payment-Currency: sat
```

**X-Payment-Description**: Optional description

```
X-Payment-Description: Access to premium API endpoint
```

## Example Usage

### Without Payment

```bash
curl http://localhost:3001/api/protected/hello
```

**Response:**
```
HTTP/1.1 402 Payment Required
X-Payment-Link: bitcoincash:...?amount=0.00001&op_return=464c4f5701api_access
X-Payment-Amount: 1000
X-Payment-Currency: sat

{
  "error": {
    "code": "PAYMENT_REQUIRED",
    "message": "Payment required to access this resource",
    "payment_link": "bitcoincash:...",
    "payment_amount": 1000,
    "payment_currency": "sat",
    "protocol": "Blinch",
    "protocol_prefix": "464c4f5701"
  }
}
```

### With Payment

```bash
curl -H "X-Payment: YOUR_TX_ID" http://localhost:3001/api/protected/hello
```

**Response:**
```
HTTP/1.1 200 OK

{
  "message": "Hello! You have successfully paid for access.",
  "timestamp": "2026-02-16T12:00:00.000Z",
  "payment": {
    "txId": "YOUR_TX_ID",
    "amount": 1000,
    "verified": true
  }
}
```

Premium endpoint (5000 sats)

AI prompt template (1000 sats)

Protected generation endpoint (1000 sats)

## Integration with MCP

AI agents can use the Blinch MCP tools to automate payment:

```typescript
// 1. Get action metadata
const metadata = await mcp.callTool({
  name: 'get_action_metadata',
  arguments: { id: 'api_access' }
});

// 2. Create payment link
const payment = await mcp.callTool({
  name: 'create_blinch_link',
  arguments: {
    amount: metadata.amount,
    recipient: metadata.recipient,
    action_type: 'api_access'
  }
});

// 3. Sign and broadcast transaction (using wallet)
const txId = await wallet.signAndBroadcast(payment.url);

// 4. Retry request with payment
const response = await fetch('http://api.blinch.network/api/protected/data', {
  headers: {
    'X-Payment': txId
  }
});
```

## Security

- All payments are verified on-chain
- OP_RETURN must contain `464c4f5701` prefix
- Minimum confirmations required (configurable)
- Amount and recipient verified
